## 문제

24시간 해커톤(AGENT24)에서 처음 만난 4명이 만든 학습 도우미다. 대학 강의안 PDF를 넣으면 에이전트가 단원·소주제·개념 노드·문서를 만들어 지식그래프를 세우고, 이후 학습 대화를 넣으면 그래프를 확장하면서 학생이 어디서 막혔는지를 대화 원문 인용과 함께 표시한다. 나는 에이전트 코어와 데이터 계약을 맡았고, 팀원 세 명이 각자 다른 환경에서 병렬로 개발할 수 있는 기반을 만드는 일이 첫 과제였다.

## 결과

이 결과물로 팀은 AGENT24에서 Best Creative Agent 상을 받았다. 심사 기준은 주최 측의 것이라 특정 수치와 연결해 설명하지 않는다.

한 실행의 스트림에는 두 층이 실린다. 하부 API 원본 이벤트를 가공 없이 담는 raw 층과 판단 근거·툴 호출·결과 요약으로 이루어진 요약 층이다. 두 뷰를 가르는 규칙을 "요약 층이 비고 raw만 있으면 원본 통과분"이라는 한 줄로 정의해, 프론트 담당자가 별도 협의 없이 토글을 구현했다. 대회 규칙(원본 이벤트 실시간 출력)과 사람이 읽는 화면을 한 스트림으로 만족한 셈이다.

배포본은 강의안 PDF, 붙여넣은 대화, ChatGPT 공유 링크 세 가지 입력을 받는다. 공유 링크는 공식 API가 막혀 있어 페이지에 박힌 페이로드를 직접 풀어 메시지를 추출한다. 실행 뒤 되돌리기·다시 실행은 그래프 스냅샷으로 처리한다.

## 한계와 다음 단계

- 그래프 상태가 세션별 JSON 파일 하나다. 다중 사용자·다중 인스턴스로 가려면 저장 계층부터 바꿔야 한다.
- 24시간 병렬 개발의 결과물이라 코드 통일성과 예외 처리에 부채가 남아 있다.
- 배포본에는 접근 제어가 없다. 동시 실행 상한은 메모리를 지키는 장치이지 비용을 막는 장치가 아니며, 시연이 끝나면 내리거나 키를 회수해야 한다는 점을 문서에 남겼다.
- 판단 근거를 남기게 하는 설계가 모든 판단이 타당함을 보장하지는 않는다. 근거 없이 툴만 부른 턴은 근거를 지어내지 않고 비워서 내보낸다.
